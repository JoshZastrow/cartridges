# Multi-agent instructions: implementing the duplex speech cartridge

Companion to `docs/plans/duplex-speech-cartridge.md` (the plan: survey,
requirements, spec). Tracking: epic #7, issues #8–#18 on the Cartridges
board. This file says how several Claude Code agents build it without
tripping over each other. The rules in `CLAUDE.md` (claim an issue before
working, worktree per issue, never commit to `main`, Status on the board is
the truth) apply unchanged; this file only adds what is specific to this epic.

## 1. What we are building, in one paragraph

A trained KV prefix ("cartridge") for NVIDIA PersonaPlex 7B that replaces its
voice-prompt + text-prompt with learned keys and values per temporal layer,
so that the model **talks as the author**: in the author's voice and
prosody, in the author's diction, in the first person, and with content
lifted more or less verbatim from the author's journal. This is not the text
cartridge's job (answer facts and insights *about* the author). It is a
conversational self-portrait: asked "how have you been feeling lately?", the
model tells the story from the most recent journal entry in the author's own
sentences; asked "how have you changed over the years?", it answers "in 2024
I believed <what the author wrote then>, but lately I've been focusing on
<what the author wrote recently>". The cartridge is initialised from a
prefill of the author's voice clip, a persona text and a journal digest, then
trained by self-study on synthetic conversations whose answers are composed
from the author's own journal sentences and rendered in the author's voice
(stage 1), then refined on its own rollouts (stage 2). The base model stays
frozen. Serving needs a pinned prefix region in the ring KV cache so the
cartridge is never evicted.

## 1b. Target behaviour and dataset design

This section overrides plan §3.2 D3–D5 and the question-answering framing
of issues #9, #10, #11 and #13 where they differ. The issue bodies still
describe the fact-answering version; follow this section.

**Target behaviour.** With the cartridge and no other prompt, PersonaPlex:

1. speaks in the author's voice (acoustic identity and prosody);
2. speaks in the author's diction: the author's words, sentence shapes,
   recurring phrases and rhythm, in the first person, spoken register;
3. answers conversational prompts with the author's own journal content,
   retold rather than summarised: stories, ideas, moods, as written;
4. respects time: "lately", "these days" map to the most recent entries;
   "over the years", "back then" produce chronologically ordered contrasts
   between entries at least a year apart;
5. never produces content about sexuality or anger, and declines gently
   in character if asked;
6. keeps PersonaPlex's duplex behaviour (backchannels, interruptions).

**Unit of data: the passage.** A passage is one to several consecutive
sentences from one journal entry, with its date and page. Passages are the
only source of response content. The Qwen Teacher (full journal) selects
them; it does not paraphrase them.

**Topic exclusion, first.** Before any question is written, the Qwen Teacher
labels every passage with one of `{sexuality, anger, other}` (plus a
`borderline` flag). `sexuality`, `anger` and `borderline` passages are
removed from the pool and from the digest. A second classifier pass runs on
every generated response and every teacher rollout transcript; any hit is
dropped and counted. The counts go in the #10 summary comment. The held-out
eval includes 20 prompts that invite those topics, to measure the
in-character decline (target: 0 violations).

**Questions.** Conversational, the kind a friend asks, generated by the Qwen
Teacher *from* the selected passages so that each has a grounded answer.
Three families, roughly 50 / 30 / 20:

- *Story* (one passage): "how have you been feeling lately?", "what's been
  on your mind?", "tell me about <place/person/project named in the
  passage>", "what happened with <event>?".
- *Change* (two or more passages ≥ 1 year apart): "how have you changed
  over the years?", "do you still think that about <topic>?", "what did
  you believe back then?".
- *Idea* (one passage with an opinion or reflection): "what do you make of
  <theme>?", "why does <thing> matter to you?".

The author's own questions and conversational chat prompts from the task DB
are kept as a fourth, small family; psychology-test items are dropped (not
conversational).

**Responses.** Composed by the Qwen Teacher under hard constraints, then
validated mechanically:

- ≥ 80% of response tokens appear verbatim in the source passages (measured
  as n-gram coverage, n = 4, against the passage text); the rest are bridging
  words only: dates, "back then", "lately", "and", "but".
- First person throughout; no third-person references to "the author" or
  "the journal"; no spoken citations (`[Journal:p.N]` never appears in the
  spoken text; page refs live in metadata for validation).
- Spoken register: 2–6 sentences, 10–40 s when rendered; contractions
  allowed; no lists, no headings.
- Chronology stated in words when two passages are used ("in 2024 … but
  this spring …"), in the order written.
- Passes the topic classifier.

Rejected responses are regenerated once, then the passage is skipped. Target
pool: ~3,000 train, ~200 held-out, with held-out passages disjoint from train
passages and spanning every journal year.

**Audio.** The response text is rendered in the author's voice by **Kyutai
Pocket TTS** (100M, clones a voice from one short sample, batch inference,
runs on CPU or Apple Silicon), conditioned on the author's prompt split
from `data/voice/`; aligned to words with Whisper timestamps; resampled to
24 kHz and Mimi-encoded. This is the agent audio target. The question is
rendered in other voices on the user channel (Pocket TTS with other donated
voices, or any open TTS). This replaces "teacher rollouts in PersonaPlex's
prompt voice" as the primary target: the voice we are teaching is the
author's, and the words are the author's. Pocket TTS's own similarity to
the author's held-out clips is measured first and is the ceiling; if it is
below 0.7, fine-tune Pocket TTS on the author's clips before rendering
(a sub-task of #10) rather than accepting a low ceiling.

**Objective.** Stage 1 is PersonaPlex's own SFT loss on the agent streams
(text tokens placed at their word frames with pads between, Mimi tokens of
the author's-voice audio; semantic codebook 1, acoustic 0.02, padded text
0.3), applied to the frozen model with only the cartridge trainable. A KL
term on the *text stream only* to a PersonaPlex teacher that has the source
passage in its `<system>` prompt is kept as a regulariser for fluency and
turn-taking (weight to sweep in #14; start at 0.5). Stage 2 keeps the
on-policy loop with that same teacher on the text stream and the author's
TTS as the audio reference for sampled text.

**What "good" means.** Three measures, all against held-out prompts:

- *Voice*: speaker similarity to the author's held-out clips (≥ stock
  prompt baseline, then ≥ 0.7 with the LoRA phase).
- *Diction and content*: verbatim 4-gram coverage of the transcript against
  the journal (target ≥ 0.6 on story prompts, where the ceiling set by the
  responses is ~0.8); first-person rate ≥ 0.95; a Qwen judge rubric
  `voice-v0` scoring "is this how the author writes" and "is the retold
  content actually in the journal", with the matching passages shown to the
  judge.
- *Behaviour*: duplex metrics within 10% of baseline; 0 topic violations.

  when an issue moves to Done, flips the next issues to Ready, reads every

  acceptance list and the contracts in section 5, nothing else.

## 4. Shared conventions for this epic

- **The voice project is its own package, isolated from the cartridge
  work.** It lives in `voice/` at the repo root, as a uv workspace member
  named `voice`, with its own `pyproject.toml`, `src/voice/`, `tests/`,
  README, Modal apps, volumes, W&B project and CLI. Nothing under
  `src/cartridges/` changes for this epic, and nothing in `voice/` imports
  `cartridges.*`. The text cartridge's training, evals, gateway and vLLM
  serving stay exactly as they are.

  ```
  voice/
    pyproject.toml          # member "voice"; depends on "shared", torch, modal, wandb,
                            # the pinned PersonaPlex moshi fork, pocket-tts, whisper
    README.md
    src/voice/
      model.py              # load PersonaPlex + Mimi + SentencePiece, freeze
      cache.py              # VoiceCartridge (K/V prefix), training-forward patch
      patches/              # pinned-prefix RingKVCache, applied at import
      prompt.py             # voice clip + persona + digest -> init frames
      passages.py           # journal -> dated passages, topic labels
      data.py               # questions, responses, validators, dialogue/frames IO
      tts.py                # render_author (Pocket TTS), render_other
      teacher.py            # passage-prompted PersonaPlex teacher (text-stream targets)
      train.py              # stage 1 SFT+KL, stage 2 on-policy; Modal app "voice-train"
      evals.py              # Whisper, speaker sim, coverage, judge glue, duplex metrics
      serve.py              # --cartridge flag for moshi.server / moshi.offline
      deploy.py             # Modal app "voice-serve": the PersonaPlex server with a cartridge
      hertz/                # optional #18 pilot, isolated
    tests/
  shared/
    pyproject.toml          # member "shared": components both projects need
    src/shared/
      teacher.py            # Qwen Teacher client (vLLM on Modal), context block, render
      tracking.py           # W&B runs and artifacts
      judge.py              # rubric judge over a generate() callable; rubric loader
      targets.py            # top-k target shard read/write (with a stream column)
      optim.py              # relative-LR Adam with warmup, EarlyStopping
    tests/
  src/cartridges/           # untouched
  ```

- **The shared library is copied out, not moved.** `shared/` starts as
  adapted copies of `cartridges.cartridge.{teacher,tracking,tasks.judge,
  tasks.targets}` and the optimizer and `EarlyStopping` from
  `train_distill.py`, with the journal-specific assumptions (citation
  reminder, page-tree paths, Qwen-only prompts) made explicit parameters.
  The cartridge package keeps its own copies until a separate issue, after
  the open cartridge PRs land, switches it to import from `shared`. Until
  then the two copies may drift; that is accepted so this epic never edits
  cartridge files. Anything voice needs from the cartridge repo beyond those
  five modules is copied into `shared/` the same way, with a comment naming
  its origin.
- **Deployment and serving are separate too.** The voice server is
  PersonaPlex's own WebSocket server with the cartridge loaded (`deploy.py`,
  Modal app `voice-serve`), not the LibreChat gateway or vLLM. Volumes are
  `voice-data` (passages, dialogues, frames) and `voice-voice` (the author's
  clips); W&B project `voice`; CLI entry point `voice` (`uv run voice ...`).
- **PersonaPlex is vendored and pinned.** The `moshi` fork from
  `NVIDIA/personaplex` at commit `3428dfd`, a git dependency in
  `voice/pyproject.toml` and installed into the Modal image from
  `voice/src/voice/train.py` (#8 sets this up; everyone else reuses the
  image). Patches to the fork (#12) live in `voice/src/voice/patches/` and
  are applied at import, not committed into the vendored tree.
- **GPU work runs on Modal, `gpu="H200"`.** Every GPU entry point has a
  `--dry-run` that runs on CPU with a tiny fixture before spending money.
  Spend cap per issue: $40 unless the issue says otherwise; post the W&B
  run and cost in the summary comment. Phase 1 total is estimated at
  $160–200 and exceeds the cap recorded in `docs/plans/next-experiments.md`,
  so the coordinator confirms budget with the author before wave 3.
- **The author's voice.** `data/voice/josh-thoughts-1.m4a` (about 9.8 min,
  git-ignored). #10 converts it to 24 kHz mono WAV at −24 LUFS, splits it
  80/10/10 (TTS prompt and cartridge init / Pocket TTS fine-tune if needed /
  speaker-similarity eval), and uploads it to the Modal Volume
  `voice-voice` with a manifest. Nothing under `data/` is ever
  committed, uploaded to W&B as a public artifact, or pasted into an issue.
  Treat it as personal data.
- **Author-voice TTS is Kyutai Pocket TTS.** All agent-side renders (training
  targets in #10, sampled-text audio references in #15, the ablation in #16)
  use it, from one wrapper `tts.py: render_author(text) -> wav24k`, so every
  issue teaches the same voice. The wrapper also exposes
  `render_other(text, voice_id)` for user-channel questions.
- **Tests.** Every module has a CPU test with synthetic tensors or audio
  under `voice/tests/` (and `shared/tests/` for the library), run with
  `uv run --package voice pytest`. The parity fixture from #8 (stored logits
  of the stock prompt path) is the one GPU-derived fixture and is committed
  once, small (10 dialogues, 50 frames each, top-20 only).
- **Tracking.** W&B project `voice`, run group `voice-<issue>-<short>`,
  artifact type `voice-cartridge`.
- **Style.** Match `cartridges/cartridge/cache.py`: pure functions where
  possible, IO injected, Pydantic configs, docstring at the top of each
  module stating the shapes. Same ruff settings as the root.

## 5. Interface contracts (owned by the first issue that ships them)

Later issues code against these. Changing one means a comment on every issue
that consumes it, before the change.

**Shared library (from #19)**
```
shared.teacher.Teacher          # Qwen on vLLM/Modal: generate(messages, max_tokens, logprobs, temperature)
shared.teacher.render(tokenizer, messages, context) -> (prompt_ids, ...)
shared.tracking.start_run(project, group, config) / log_artifact(run, path, type)
shared.judge.judge(answers, tasks, references, generate, rubric) -> (rows, summary, details)
shared.targets.write_shard(rows, uri) / read_shards(uris) ; TargetRow has a `stream` field
shared.optim.make_optimizer(params, lr, relative_lr, warmup_steps) ; EarlyStopping(patience, save)
```

**Cartridge (from #8)**
```
VoiceCartridge(keys: list[Tensor[1,32,p,128]], values: ..., num_frozen_tokens=1, meta: dict)
VoiceCartridge.from_prefill(lm_model, frames: Tensor[1,17,p]) -> VoiceCartridge
VoiceCartridge.init_from_prompt(lm_model, mimi, spm, voice_wav, persona_text, digest_text, p) -> VoiceCartridge
VoiceCartridge.save(dir) / .load(dir)           # cartridge.safetensors + cartridge.json
with cartridge.patched(lm_model, batch_size):   # training forward: cartridge K/V prepended, RoPE offset p
    out = lm_model.forward(codes)               # codes [B,17,T]; out.text_logits [B,T,32000], out.audio_logits [B,8,T,2048]
```
`cartridge.json`: `{base_model, fork_commit, p, num_frozen_tokens, voice_sha,
persona, digest_sha, stage, step}`.

**Passages and dialogues (from #10)**
```
passages.jsonl: {passage_id, entry_date (YYYY-MM-DD), pages [int], text, topic (sexuality|anger|other), borderline (bool)}
dialogue.jsonl: {id, family (story|change|idea|author), split, question, response_text,
                 passage_ids [str], coverage (float), user_wav, agent_wav, words [{w, start_s, end_s}]}
frames/<id>.safetensors: user_audio int16 [T,8], agent_text int32 [T], agent_audio int16 [T,8]
```
`agent_wav` is the author's-TTS render of `response_text`; `words` are its
Whisper word timestamps; `agent_text` places each word's SentencePiece
tokens at its start frame with PersonaPlex's pad id between words;
`agent_audio` is Mimi of `agent_wav`. Frames are 12.5 Hz, 8 codebooks,
vocab 2048. Only `topic == other` and `borderline == false` passages appear
in any dialogue.

**Teacher text-stream targets (from #13, optional regulariser)**
```
parquet shard: id, frame, stream (0 only), topk_ids int32[20], topk_logprobs float32[20]
```
The PersonaPlex teacher with the source passages in its `<system>` prompt,
teacher-forced on the dialogue's own frames; text stream only. Written with
`shared.targets` (stream column); read by #14, #15.

**Eval CLI (from #9)**
```
uv run voice eval --cartridge <dir|none> --tasks <jsonl> --out <dir>
```
Writes `report.json` with the rows of plan §3.5 plus the section 1b
measures (verbatim coverage, first-person rate, `voice-v0` judge scores,
topic violations), each `{value, ci_low, ci_high, n}`, and logs to W&B.
Baseline run name `duplex-baseline-stock`.

**Server flag (from #12)**
```
python -m moshi.server --cartridge <dir>    # fills the pinned region, skips step_system_prompts
python -m moshi.offline --cartridge <dir> --input user.wav --output agent.wav
```

**Trainer (from #14, extended by #15, #16)**
```
uv run voice train --config <toml>     # stage: sft | onpolicy | ablation
```
Config is a Pydantic model in `voice/src/voice/train.py`; every stage reads
the same `VoiceCartridge` and writes the same artifact.

**Deploy (from #12)**
```
uv run voice deploy --cartridge <wandb-artifact|dir>   # Modal app voice-serve, WebSocket endpoint
```
